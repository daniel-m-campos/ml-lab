# bonsai in-house MLOps baseline

Inventory of what the bonsai repository (`/Users/danielmcampos/work/mpcs/bonsai`, C++23/CUDA GBT library with a Python package `bonsai-gbt`) already runs as an in-house MLOps system, read at main `a793136a` on 2026-10-02. Six areas, each ending with general / bonsai-specific / missing. File paths are repo-relative unless absolute.

## 1. Benchmark harness: `python/bonsai/bench/`

### Vocabulary

| term | definition | where |
|---|---|---|
| spec | JSON file naming `name, suite, defaults, cells, variants, threads, repeats, gates, timeout_cap`; unknown top-level keys are a `ValueError` | `spec.py` `_SPEC_KEYS`, `load_spec` |
| cell | one fully defaulted dict of knobs: `rows, cols` (required), `bins, depth, iters, lr, seed, min_data_in_leaf, lambda_l2` (defaulted from `params.SCALING`), `informative=20`, `contribs=False`, `axis="cell"`, `n_test=min(rows//5, 500_000)`, `bins_effective=bins`; per-cell optional `task, eval_mode, eval_frac, patience, num_leaves, timeout_s, tag, folds, scheme, strategy` | `spec.py` `make_cell`, `_CELL_DEFAULTS` |
| variant | one arm: `Variant(name, lib, device, aliases)`; 12 canonical names (`bonsai_depthwise, bonsai_leafwise, bonsai_levelwise, bonsai_cuda_depthwise, bonsai_cuda_leafwise, bonsai_cuda_levelwise, xgb_hist, xgb_cuda, lgbm_cpu, lgbm_cuda, catboost_cpu, catboost_gpu`); aliases are the spellings older committed rows carry (`bonsai_dw, bonsai_lw, bonsai_obl, xgb, lgbm, catboost, *_gpu, *_cpu`); `resolve(name)` raises `KeyError` on unknowns | `variants.py` `_TABLE`, `REGISTRY`, `_BY_ALIAS` |
| job | `{cell, variant, threads, repeats}`; `expand(spec)` iterates cells outer, variants, threads inner; repeats policy is an int or `{cpu: n, cuda: n, default: n}` keyed by the variant's device | `spec.py` `expand`, `_repeats_for` |
| run row | one JSONL line per attempt (ok or status row), schema v1 | `runlog.py` `emit_row` |
| run label | `--run-label` (default: spec name); part of the resume key; pod writes `standings-<axis>-<YYYY-MM>` | `cli.py`, `driver.py` `_job_key` |

Spec defaults are knob-checked: a key outside `_CELL_DEFAULTS` in `defaults` is a `ValueError` (the drift class that twice produced a false conclusion, `params.py` docstring). Per-cell keys stay open.

### Bundled specs (`python/bonsai/bench/specs/*.json`)

`cpu-tall` (2097152x128, 12t, 4 reps, cap 3600), `cpu-wide` (16384x16384, `timeout_s` 7200, 2 reps), `gpu-tall` (16777216x128, 16t, 2 reps), `gpu-wide` (131072x16384, `gates.gpu_max_cols=null`), `gpu-extreme` (16777216x1024, 1 rep, `gates: {mem_gate: off, gpu_max_cols: null}`, cap 10800), `gpu-early-stop` (three cells with `eval_mode` off/eval/stop, the stop cell at iters 2000 lr 0.05 patience 50), `gpu-shap` (`contribs: true`, 500 iters, four cells), `cv-folds` and `gpu-cv-folds` (cells with `folds, scheme walk_forward|shuffled, strategy view|copy`), `scaling-rows/cols/bins/threads` (suite `scaling`, 11 variants, 1 rep; threads spec sweeps `[1,4,16,64]`). An axis name equals its spec name equals its results file stem.

### CLI (`cli.py`, `python -m bonsai.bench`)

Subcommands: `run --spec <bundled-name-or-path> [--out] [--run-label] [--host-name] [--variants a,b] [--repeats N] [--timeout-cap N] [--resume <jsonl>] [--no-resume] [--dry-run] [--no-mem-sampler] [--data-cache DIR]`; `plan` (same flags, dry run); `variants [--device cpu|cuda]`; `specs`; `worker` (internal: job JSON on stdin, prints `RESULT <json>` on stdout). Default `--out` is `benchmarks/results/<name>.jsonl` inside a checkout (`runlog.repo_root()` walks up to the dir with `pyproject.toml` and `benchmarks/`), else the bare name. Resume defaults on when the out file exists. `knobs` written to every row = spec `defaults` plus `num_leaves_convention: "full"`.

### Driver (`driver.py`): one child process per attempt

- `run_one(spec, timeout, sampler, data_cache)`: `Popen([sys.executable, "-m", "bonsai.bench", "worker"])`, job JSON over stdin, `communicate(timeout=...)`. Timeout: `proc.kill()` then a 30 s bounded reap (`_kill_wedged`), row `status=timeout, message="exceeded {timeout}s"`.
- Exit classification (`_row_from_exit`, `_signal_row`, `classify_error`): negative return code -> `SIGKILL` reads `oom`, any other signal `error`, message `killed by signal N`; nonzero exit or no `RESULT` line -> classify the WHOLE stderr by keyword: `oom` (`out of memory, memoryerror, bad_alloc, cannot allocate, oom, cudaerrormemoryallocation`), `unsupported` (`unsupported, max_bin, border_count, invalid parameter, must be`), else `error`; message = last stderr line that is not noise (`[bt]`, `Stack trace`, profile prefixes), truncated to 300 chars.
- Timeout per cell: `timeout_for(cell) = max(900, 90 * rows*cols/1e8 * max(1, iters/100) * (1 + cols/16384))`, overridden by cell `timeout_s`, capped by spec/CLI `timeout_cap` (default 3600).
- Gates (`skip_reason`): CUDA variant on a host with `gpu None` -> `skipped`; `cols > gpu_max_cols` (default 16384, spec can null it) -> `skipped`; `est_dev_gb = (rows*cols*2 + rows*8 + 512 MiB)/GiB > 0.85 * gpu_vram_gb` -> `skipped`; bonsai `bins > 65535` -> `unsupported` ("bin_id_t is uint16"); `est_host_gb = (rows+n_test)*cols*6*factor/GiB` (factor 4.0 catboost else 3.0) `> 0.8 * ram_gb` -> `skipped`; `axis == threads` and `threads > n_vcpu` -> `skipped`. `gates` keys allowed: `mem_gate`, `gpu_max_cols` (`ValueError` otherwise). A skip is emitted as a status row once (repeat 0) unless already in the resume set.
- Resume (`resume_keys`, `_job_key`): key = `(variant, threads, repeat, rows, cols, bins, depth, iters, seed, eval_mode, host.name, run)`. `ok` and `unsupported` are final; `skipped/oom/timeout/error` re-attempt. Rows without a `cell` dict (older schemas) are ignored. Host and run label are in the key so a second host appends rather than resume-skips.
- Dry run (`_print_dry_plan`): prints variant, threads, shape, timeout, repeats and `resume-skip=k/n`, runs nothing, creates no dirs.
- `_bins_effective`: catboost GPU with `bins > 255` records `bins_effective=255` (border cap 254).
- Device memory sampler (`DeviceMemSampler`): daemon thread, 0.25 s interval, prefers NVML (`pynvml`, attributes memory to the child pid inside a container) with `nvidia-smi --query-compute-apps` fallback; device index = first entry of `CUDA_VISIBLE_DEVICES`; result block `dev_mem = {peak_gb_pid, peak_gb_total, samples, interval_s, source: nvml|nvidia-smi|injected, stopped_early?}`; only runs for CUDA variants unless `--no-mem-sampler`.
- Worker env (`_worker_env`): bonsai arms get `BONSAI_GROW_PROFILE=1 BONSAI_INGEST_PROFILE=1 BONSAI_CUDA_PROFILE=1 BONSAI_FIT_PROFILE=1` unless `BONSAI_BENCH_NO_PROFILE` set; `BONSAI_BENCH_DATA_CACHE` passed through.
- Profile parsing (`parse_profiles`): stderr lines with prefixes `cuda-profile:, grow-profile:, ingest-profile:, fit-profile:, cuda-upload-decomp:, cuda-round-decomp:, cuda-level-decomp:, cuda-part-decomp:` are parsed by `(\w+)=([\d.]+)s?` into a flat `profile` dict keyed `<prefix>_<bucket>` (e.g. `cuda-round-decomp_adv_hist`, `cuda-level-decomp_rows_l1`).

### Worker and runners (`runners.py`)

- `worker(spec)`: generate data (`gen_data` or `cached_gen_data` when `BONSAI_BENCH_DATA_CACHE` set), dispatch on `resolve(variant).lib` via `RUNNERS = {bonsai, xgb, lgbm, catboost}`; CUDA arms pay an untimed micro-fit first (8192 rows, 1024 test, 5 iters) to absorb context creation and PTX JIT; a cell with `folds` routes to `cv.run_cv`. Adds `peak_rss_gb` (ru_maxrss, KiB on Linux, bytes on macOS), `fit_rows_per_s`, `predict_rows_per_s`, optional `contribs_rows_per_s`, rounds seconds to 3 dp and r2 to 4 dp, and `libs` (the child's imported `bonsai, xgboost, lightgbm, catboost, numpy` versions, folded by the parent into `host.libs`).
- Phases (`_phase` context manager): `fit_s` is the OUTER wall clock; `ingest_s` and `train_s` nest inside it and are never summed back; `predict_s` times prediction over the raw test matrix; `contribs_s` optional TreeSHAP phase plus `contribs_additivity` = max_i |sum_j phi_ij - margin_i| / max(1, |margin_i|).
- Library wrapping, each at the shared knobs from `params.py` (never hand-derived): bonsai `Dataset(X, y, max_bin, n_threads, device="cuda"|"cpu")` then `train(pairs minus bin_mapper.*, ds, eval_set)`, or fused `train(pairs, X, y)` when `spec.fused`; xgboost `QuantileDMatrix(X, label, max_bin)` + `xgb.train(params, num_boost_round)`, `inplace_predict(iteration_range=(0, best_iteration+1))` on a stop; lightgbm `lgb.Dataset(X, label, params).construct()` + `lgb.train`, `lgb.early_stopping` callback; catboost `Pool(X, label)` + `CatBoostRegressor/Classifier(**core, iterations, loss_function, task_type GPU|CPU, devices="0", thread_count)`, `od_type="Iter", od_wait` for patience, `use_best_model=False` on a fixed-iteration eval arm.
- Placement guard (`assert_xgb_trained_on_device`): after a `device=cuda` fit reads `json.loads(booster.save_config())["learner"]["generic_param"]["device"]` and raises `RuntimeError("unsupported: xgboost silently fell back to CPU ...")` unless it starts with `cuda`. No equivalent for lightgbm or catboost (they raise rather than fall back; their params echo the request).
- Early stopping: `eval_split` carves `eval_frac` (default 0.1) off the TRAIN tail; modes `off` (carve and discard), `eval` (hand over, no patience), `stop` (patience from cell, default 50); rows gain `eval_mode` and `stopped_at` (RETAINED round count in every library's spelling) only when `eval_mode` is set.
- Data cache (`cached_gen_data`): key `r{DATA_RECIPE}-{rows}x{cols}-s{seed}-i{informative}-t{n_test}`, four `.npy` files written via `os.replace`, FULL read not memmap (memmap deferred page faults into fit and read 12% slow); declines to the generator when `2*(rows+n_test)*cols*4 > 0.6 * usable_ram_gb`.

### Params (`params.py`)

`CAMPAIGN = dict(iters=200, lr=0.05, depth=6, bins=255, min_data_in_leaf=20, lambda_l2=1.0, seed=42)` (quality), `SCALING = dict(iters=100, lr=0.1, depth=8, ...)` (perf), `EARLY_STOP = dict(iters=2000, lr=0.05, patience=50, eval_frac=0.1)`. Builders `bonsai_core` (dotted key pairs: `dispatch.grower_name, dispatch.objective_name, booster.n_iters, booster.learning_rate, booster.random_seed, tree.max_depth, tree.max_leaves, tree.min_data_in_leaf, tree.lambda_l2, bin_mapper.max_bin, parallel.n_threads, booster.early_stopping_rounds`), `xgb_core` (via `bonsai.interop.to_xgboost`, `tree.min_child_hess` <- min_data_in_leaf, `tree_method=hist`), `lgbm_core` (`verbose=-1`), `catboost_core` (bins-to-borders fencepost in interop, GPU `border_count<=254`). Leaf conventions: `num_leaves_campaign(d) = (1<<d)-1`, `num_leaves_full(d) = 1<<d`, `leaf_bound_depth(n) = n-1`.

### Row schema v1 (`runlog.py`, every field)

Base, written by `emit_row`: `schema=1`, `ts` (UTC ISO seconds), `git_sha` (`BONSAI_BENCH_GIT_SHA` env wins, else `git rev-parse --short HEAD` in cwd, else `"unknown"`), `division` in `("quality","perf")`, `suite`, `script` (`__main__.__file__`), `cmd` (`sys.executable + argv`), `timing_mode` in `("in_memory","pipeline")` or null, `host` (block below), `knobs` and `knobs_hash` (8 hex of sha256 over `json.dumps(knobs, sort_keys=True, separators=(",",":"))`).

Host block (`detect_host`): `name` (`--host-name` or `platform.node()`), `gpu` (nvidia-smi name), `driver`, `gpu_vram_gb`, `cpu_model`, `n_vcpu` (`sched_getaffinity` length), `cpu_quota` (min of CFS quota cores from `/sys/fs/cgroup/cpu.max` or v1 `cpu.cfs_quota_us/cpu.cfs_period_us`, and cpuset cores when the affinity mask is smaller than `os.cpu_count()`; null when uncapped), `omp_wait_policy` (env), `ram_gb` (min of machine RAM and cgroup `memory.max` / v1 `memory.limit_in_bytes`, v1 sentinel >= 2**62 means unlimited), `os`, `python`, `libs` ({bonsai, xgboost, lightgbm, catboost, numpy} versions, only those imported).

Perf row (driver `_Sink.emit`): `dataset="synthetic-friedman1"`, `data_recipe=2`, `task="reg"`, `cell` (dict), `variant`, `threads`, `repeat`, `run` (label), `status` in `ok|skipped|unsupported|oom|timeout|error`, `message`, `fit_s`, `ingest_s`, `train_s`, `predict_s`, `r2_train`, `r2_test` (or `auc_test` for binary), `peak_rss_gb`, `fit_rows_per_s`, `predict_rows_per_s`, `profile` (dict or null), `dev_mem` (block or null, CUDA only); optional `eval_mode`, `stopped_at`, `contribs_s`, `contribs_additivity`, `contribs_rows_per_s`; cv rows add `loop_s, fit_loop_s, score_loop_s, folds, r2_folds`.

Quality row (`grinsztajn.py`): `division="quality"`, `suite` in `num_reg|num_clf|cat_reg|cat_clf` (OpenML suites 297/298/299/304), `knobs` = CAMPAIGN + `leaves, regime, train_cap`, `dataset`, `task` (`r2|auc`), `variant` (short alias), `seed` in (0,1,2), `kind`, `metric` (name), `value`, `status` (`ok` or `error: ...`[:200]), `n_train`, `n_features`, `fit_s`. Resume key `(suite, dataset, variant, seed)`. Regimes: `campaign` and `leaf-capped` (63 leaves, depth 62); `--device cuda` sweeps the GPU arm set.

Pre-schema rows exist in committed files (number in `metric` instead of `value`); readers tolerate both (`_value`, `check_standings.quality_value`).

### Datasets and metrics

`datasets.py`: `REGISTRY` of `Dataset(name, tier, task, source, license_note, split, files)` with tiers `test-pin, quality-external, quality-smoke, perf-scale, perf-synthetic`; `data_root()` = `BONSAI_BENCH_DATA` env, else `tests/data` found by walking up, else `~/.cache/bonsai-bench`; `fetch(name, force)` idempotent with stdlib streaming fetchers; `python -m bonsai.bench.datasets --list`. `synth.py`: generalized Friedman-1, `DATA_RECIPE=2`, `N_BLOCKS=64` row blocks off `SeedSequence([seed, rows, cols]).spawn(65)`, byte-stable in `(rows, cols, seed, n_test)` and pinned by golden hashes in `test_synth.py`; a byte change requires a recipe bump. `metrics.py`: `r2, rmse, mae, acc, auc (sklearn or exact rank fallback), additivity`.

### Area 1 verdict

General: spec -> cell x variant x threads x repeats expansion; one subprocess per attempt with status rows for OOM/timeout/signal; resume keyed on (identity, host, run label) with final vs retryable statuses; schema-versioned additive JSONL rows with `git_sha, cmd, host, knobs_hash`; cgroup-aware host detection (quota, cpuset, memory.max); per-pid device memory sampler; untimed warm-up for JIT; outer-wall-clock plus nested phases; keyword error classifier; dry-run planner; alias registry so old row spellings stay readable; data cache keyed on recipe.
bonsai-specific: the variant table and library wrappers; the Friedman-1 generator; `params.py` knob translations; profile prefixes; `bin_id_t` uint16 gate; eval-mode and contribs phases; the `interop` renaming.
Missing: no run database (JSONL files only, grouped by convention); no schema validator for rows (readers tolerate extra keys, nothing rejects a malformed one); `git_sha` is short-or-long depending on source (`BONSAI_BENCH_GIT_SHA` full vs `rev-parse --short`), compared by prefix downstream; `knobs_hash` is computed over spec defaults not the per-cell knobs, so it does not identify a cell; host `name` for the quality axis is the container id (`dfdb72f57971`), not the tag; no row carries the harness version or the spec file hash; no comparison of r2 across arms is enforced in the harness (render does it later); the A/B script (`standings_ab.py`) emits a different, host-less row shape.

## 2. Results lifecycle: `scripts/standings_refresh.py`, `standings_refresh_pod.sh`, `update_standings.py`, `check_standings.py`, `standings_ab.py`, `pod_bench_driver.sh`

### Pod rental (`standings_refresh.py measure`)

- Commands: `python3 scripts/standings_refresh.py measure [--axes a,b] [--prev-version X] [--out-dir D] [--keep-pod] [--only-stale] [--cpu-plane-host gpu|cpupod] [--cpu-vcpu 16] [--gpu-type NAME] [--dry-run]`; `supersede --results-dir D [--axes] [--no-pr] [--no-parity]`.
- RunPod REST v2 (`REST = https://api.runpod.io/v2`, `_api()` with `Authorization: Bearer $RUNPOD_API_KEY`, `User-Agent: bonsai-standings-refresh`, key never printed). Catalog `GET /catalog/gpus?include=AVAILABILITY&cloud=SECURE&product=POD` -> `stocked_datacenters(gpu_type)` ranked `HIGH, MEDIUM, LOW`, `BANNED_DATACENTERS=("EUR-IS-2",)`. Create body `{name: bonsai-standings-<plane>-<YYYYMMDD-HHMM>, image: ghcr.io/daniel-m-campos/bonsai-ci:cuda12.8, cloud: SECURE, ports: ["22/tcp"], env: {PUBLIC_KEY}}` plus GPU `{gpu: {id, count: 1}, disk: 80, dataCenterIds: [dc]}` walking `GPUS = (RTX PRO 6000 Blackwell Server Edition, Workstation Edition)` per stocked datacenter then unpinned, or CPU `{cpu: {id: cpu5g, vcpuCount: 16}, disk: 30}` unpinned. Create ladder retried every `CREATE_BACKOFF_S=90` until `CREATE_DEADLINE_S=45 min`; on an `OSError` the code adopts any pod already carrying the session name (`_pod_named`) so a 500-after-placement does not bill twice. `_wait_ssh`: poll `GET /pods/{id}` `runtime.ports` for private 22 (900 s), then ssh probe (600 s). Script is scp'd and launched detached (`nohup ... > /root/refresh.log 2>&1 &`). `_poll_pod_run`: every 120 s scp `/root/standings/*` back incrementally, `tail -2 /root/refresh.log`, finish on `STANDINGS_REFRESH_DONE`; abort on `POLL_MAX_MISSES=20` consecutive ssh failures or deadline `45 min + 45 min * n_axes`. `finally`: `DELETE /pods/{id}` and `_sweep` deletes every pod whose name starts `bonsai-standings`.
- Sessions (`_sessions`): default `[(gpu, all axes), (cpu, [])]`, the CPU pod rented for the cpu A/B alone; `--cpu-plane-host cpupod` moves `cpu-*` axes onto the CPU pod. `_cpu_pod_sized`: `--cpu-vcpu >= max(spec threads)` or exit 1.
- Pre-flight: `registry_drift()` fails when `set(AXES) | set(LOCAL_AXES)` != registry keys (issue #433: 1.15.0 shipped two axes no pod branch could measure). `--only-stale` intersects with `check_standings.py --stale`. `_delivered`: fails if `quota-fail.txt` came back or any requested axis has neither `<axis>-*.jsonl` nor `QUOTAFAIL-<axis>-*.jsonl`.
- `AXES = (gpu-tall, gpu-wide, gpu-extreme, cpu-tall, cpu-wide, gpu-early-stop, gpu-shap, quality-grinsztajn, quality-grinsztajn-gpu, quality-grinsztajn-leaf-capped-gpu)`; `LOCAL_AXES = ("code",)`; `PARITY_AXIS = gpu-tall`; `AB_AXES = {gpu: gpu-tall, cpu: cpu-tall}`; `AB_FILES = {gpu: ab-gpu.jsonl, cpu: ab-cpu.jsonl}`.

### On-pod script (`standings_refresh_pod.sh`)

Env: `AXES`, `GIT_SHA` (required), `PREV_VERSION`, `ANCHOR_VERSION`, `PLANE=gpu|cpu`, `HOST_TAG` (derived: `pod-<nvidia-smi name with dashes>` or `cpupod-<nproc>cpu`). Steps:
1. Clone, `checkout_sha`: `git fetch --tags origin '+refs/heads/*:refs/remotes/origin/*'`, `checkout --force $GIT_SHA`, assert `rev-parse HEAD == $GIT_SHA^{commit}`; else print `STANDINGS_REFRESH_FAIL checkout: ...`, write `quota-fail.txt`, print DONE with `failures=1`, exit 1. Prints `MEASURING <sha>`.
2. Build `make python-cuda` (gpu) or `make python` (cpu) with `PYTHON=/opt/venv/bin/python`.
3. `DATA_CACHE=/dev/shm/bonsai-bench-data`; `BENCH=(env PYTHONPATH=$BUILD BONSAI_BENCH_DATA_CACHE=... BONSAI_BENCH_GIT_SHA=$GIT_SHA python -m bonsai.bench)`; `CPU_BENCH` adds `OMP_WAIT_POLICY=passive`.
4. A/B arms: `anchor` (venv with `bonsai-gbt==$ANCHOR_VERSION`), `old` (`==$PREV_VERSION`), `new` (this build, PYTHONPATH). `wheel_python` creates `/root/venv-<version>` via `uv venv` + `uv pip install bonsai-gbt==V numpy psutil`. GPU A/B: cells `1000000x100` and `16000000x100`, growers `cuda_depthwise, cuda_levelwise`, 2 reps, reps outer and arms inner (interleaved), 16 threads, appended to `/root/standings/ab-gpu.jsonl`. CPU A/B (cpu plane only): growers `levelwise depthwise leafwise`, 6 reps, cell from the `cpu-tall` spec, threads from the spec, `ab-cpu.jsonl`.
5. Parity (gpu plane, only when AXES includes `gpu-tall`): 2 reps x arms `fused, two_step` of `standings_ab.py --rows 16000000 --cols 100 --grower cuda_depthwise --skip-without-cuda [--fused]` -> `parity.jsonl`.
6. `run_axis`: `gpu-extreme` skipped with a `SKIP` line if `runlog.usable_ram_gb() < EXTREME_RAM_GB=150`; `cpu-tall|cpu-wide` -> `run_cpu_axis`; other gpu specs -> `run_spec` (`run --spec A --out /root/standings/A-YYYY-MM.jsonl --run-label standings-A-YYYY-MM --host-name $HOST_TAG`); quality axes -> `python -m bonsai.bench.grinsztajn [--device cuda] [--regime leaf-capped] /root/standings/<axis>-YYYY-MM.jsonl`; unknown axis -> `fail_axis`.
7. CPU-cap gate (`cpu_cap_ok`): read `quota_cores` (cgroup v2 `cpu.max`, v1 fallback, else `unlimited`); unlimited -> need `nproc >= threads`; quota -> need `quota >= threads + QUOTA_SPARE_CORES(1)`. Then a probe fit (first variant, 1 repeat, resumes into the same file) bracketed by `throttle_counters` (`nr_periods`, `nr_throttled` from `cpu.stat`); `throttled_pct > THROTTLED_PCT_MAX(5)` or an unreadable pct -> `fail_axis`.
8. `fail_axis <axis> <why>`: prints `STANDINGS_REFRESH_FAIL <axis>: <why>`, appends to `quota-fail.txt`, renames the partial file to `QUOTAFAIL-<name>` (out of the supersession glob), increments FAILURES.
9. Always prints `STANDINGS_REFRESH_DONE axes=... ym=... host=... failures=N`; exit status is `FAILURES == 0`.

`pod_bench_driver.sh` is the ad hoc campaign variant: `HOST_TAG BRANCH SPEC OUT RUN_LABEL [DATA_CACHE]`, shallow clone, `checkout -f FETCH_HEAD`, Blackwell side-installs `cuda-toolkit-12-8` when compute cap >= 10, `make python-cuda`, one `run --spec`. No sha assertion, no gates.

### A/B row (`standings_ab.py`)

`ANCHOR_KNOBS = {lr 0.1, depth 8, bins 255, seed 42, min_data_in_leaf 20, lambda_l2 1.0, informative 20, n_test 1000}` (restated, drift-guarded by a test). Runs `runners.worker({cell, variant: bonsai_<grower>, threads, fused})` and prints one JSON line: `{arm, rows, cols, grower, fit_s, ingest_s, train_s, peak_rss_gb, r2_test, version (bonsai.__version__ or "source"), module (bonsai.__file__)}`; skipped row `{arm, grower, skipped: "no CUDA build or no visible device"}`. No host block (decision 142 notes this gap).

### Supersession (`standings_refresh.py supersede` + `update_standings.py`)

- `_cleared_parity`: reads `parity.jsonl`; medians per arm of `fit_s` and `peak_rss_gb`, `PARITY_BAND_PCT = 5`; FAIL stops the supersession; missing file FAILS unless `--no-parity` or the axes exclude `gpu-tall`; a skipped-only file passes with a caveat.

- `_restamp_and_render`: per axis `update_standings.py --axis A --file F [--companion parity-...] [--ab ab-...]`, then `git add -A benchmarks/` BEFORE `render_results.py` (the committed-files gate reads `git ls-files`).

### Benchmark protocol rules (`docs/results/benchmark-protocol.md`)

- Divisions: `quality` (metric primary, timing never citable), `perf` (every row declares `timing_mode`, accuracy only a sanity guard), `code` (self-only). Both run "closed": matched knobs, no per-model tuning.
- Only citable standings table: Grinsztajn (third-party selected tasks). Internal campaign and probes publish nothing standing.
- Scenarios are single cells chosen to make one claim (iso-volume pairs tall/wide at 2^31 and 2^28 cells, extreme at 2^34, early-stop behavior). Arms pair by growth strategy. Hardware never mixed within a table.
- Timing: `in_memory` vs `pipeline` never compared; fit_s spans ingest through model; ingest_s/train_s reported underneath, never summed back; every arm builds its own ingest structure per row; where a library bins is reported, not equalized; changing a runner's call form is a protocol change needing a same-pod A/B.
- Hardware rules: comparative numbers only from the same machine in the same session (fleet variance ~25%); interleave reps across arms; rented hosts pass a 30 s sync-latency probe (round trips over 50 us reject the pod); a reference library that falls back to CPU under a cuda request is a measurement failure (xgboost guard).
- Statistic: min over interleaved reps ("noise on a fixed workload only adds time"). Bands: 5% vs previous release, 2% vs anchor. A cell outside either band is a moved verdict.
- Standings vs evidence: evidence files frozen forever (corrections by banner plus decision entry); standings supersede in place; superseded files deleted, git history is the archive; reader prose never restates standings digits (only generated tables carry them, behind `--check`).
- Plane gating and carry-forward as in area 2; a carry-forward is legitimate only with a one-sentence unreachability argument plus a recorded check; "cost is not evidence".
- Accept gates for fixed-cost levers must be absolute time or multi-scale.
- Row schema v1 summarized; every published table names its results file and regenerating command.

### CLAUDE.md rules (summarized)

Verification floor: `make ci` before a PR; a change touching training or serialization must not move `model_hash.py`; `design_lint.py` gated metrics may not rise without `--update-baseline` in a commit that names the metric; functions over CCN 12 touched by the diff are pinned by a test and split or `left whole: <reason>` in the PR body.

### Skills (`.claude/skills/<name>/SKILL.md`, each a frontmatter `name`/`description` plus prose)

- `perf-round`: decompose -> price -> implement -> validate -> record. (1) Split every profiler line into wait/work/transfer; check conservation (parts sum to the whole; an unattributed gap is the finding, add lap counters first as their own commit). (2) Price the expected saving from measured constants before code; under ~1 s of a ~30 s fit do not spend a pod; constants drift ~25% across hosts so only play moves that win across the range. (3) `/quality-gates` per commit; instrumentation ships in the same PR. (4) Before/after on ONE pod, r2 exactly equal for behavior-preserving changes, delta vs the priced expectation; a refutation closes the PR unmerged and gets a decision entry. (5) Decision entry with measured delta and rejected alternatives; PR body carries the ledger table.
- `pod-validate`: invariants (PUBLIC_KEY at create; same-pod interleaved only; export PATH in every ssh session; sweep strays after any create failure; delete the pod when results are off; a GPU pod cannot time the CPU plane, CPU pod cpuset vs GPU pod bandwidth quota; no pod waits on a human gate without a deadline ~2x the run). Provisioning facts (cards, image tag, create error decoder, cgroup memory limit not `free`, xgboost pin `>=3.2,<3.4` and a pre-flight cuda fit). The loop: clone, `fetch`+`checkout -f FETCH_HEAD`, `make python-cuda`, build and run `[cuda]` tests; launch long work detached with `setsid nohup`, scripts end with `<NAME>_DONE` and guarded failures print `<NAME>_FAIL <why>`. Babysitting: a local watcher every ~4 min printing `procs gpu load :: log tail`, exits nonzero on script dead without DONE, triple idle, or wall-clock cap; pull results every poll. Measurement discipline: parse the LAST profile block (micro-fit prints one first); every toggle prints an engagement line; per-process NVML only; r2 EQUAL for behavior-preserving changes; conservation check; `dbin=0.00`, `bins_upload>0`, `cpu_fallback>0` mean a silent decline. The profiled ledger cell command (worker JSON on stdin with all four `BONSAI_*_PROFILE=1`).
- `quality-gates`: capture `model_hash.py` baseline BEFORE edits; per commit `make format`, `make build && ctest`, `make lint`, `model_hash.py == baseline`; never `git add -A` after format (toolchain drift reformats untouched files); Mac builds the CUDA stub so `.cu` changes need CI and a pod; a hash mismatch on a "pure refactor" means it is not pure; model-changing work gets a decision entry with before/after quality instead of the hash.
- `verify`: observe a C++ change through the Python package only; control arm is a venv with the last shipped wheel, same script run under `PYTHONPATH=build/python` and under the wheel, diff the outputs; print sha256 of `model.to_bytes()` and of `predict(X).tobytes()` plus r2; cells worth driving (tall 40000x64 depth 7, wide 6000x2300 depth 5, three growers, threads 1-4, depth 1 and 2, constant column, duplicated rows); capture `grow-profile:` per fit.
- `review-round`: (1) diff against `origin/main...HEAD`, split by language; (2) brief reviewers with the repo conventions, name uncommitted hunks, hand over suspicions as "verify or refute"; (3) ponytail (delete) before design review, narrow design review to the diff's surface; (4) verify every finding (scope via `git show origin/main:<file>`, premise via the library header, run the suite before believing a correctness fix, refute in writing in the commit message); (5) measure anything on a hot path (make the instrument resolve, swap code hold machine, quote the min); (5b) never read a gate through `tail`, `git add -u` is `-A`, lint the tree CI lints, every edit reopens every gate; (6) record applied and refuted findings in commits and PR body.
- `design-ratchet`: run `design_lint.py`, on a branch `--against <git archive origin/main export>`, read churn not totals; each rising metric is one question (clone -> which name houses both; prose -> could a name, type, or test carry it; singleton -> admission test; hardware leak -> method on the seam). Scope is the diff: per-PR scoreboard in the PR body with FIX or PIN per rising gated row; CCN > 12 on touched functions -> pin with a test then split (or `left whole:`); `lizard -Eduplicate` on touched files -> pin then house in one name; gate scripts touched -> main's copy vs branch's byte-identical over the real corpus; training touched -> `model_hash.py` unchanged; kernel or fill loop -> SASS diff or same-pod min. Altitude test (three regimes: statistical, layout, device; containment and conservation). Concept admission: a new public word needs a distinguishing rule or a measurement where the neighbour loses, recorded as a decision. Re-pin up only with a reason in the commit. Promotion ledger of reviews where a number changed the outcome.
- `feature-admission`: burden of proof on the feature; (1) prototype the benefit at zero core cost (reference-library toggle, preprocessing in Python, config-only ablation, custom-objective harness), "cannot be prototyped outside the core" is itself a finding; (2) benefit criterion: standings moved on multiple datasets at campaign knobs, deltas under the chance band are noise, coin flips declined; (3) price on named axes (core LOC, hot-path branches via `model_hash.py`, config surface, model format, guide impact, pre-registered kill criterion); (4) verdict recorded: probe script, `benchmarks/<name>-tradeoff-<date>.md` plus raw JSON, decision entry adopted / declined by measurement / deferred pending probe; declines name the reopening measurement.
- `comment-audit`: six checks (V1 restates code, V2 cross-file claim, V3 PR/issue/decision reference, V4 refactorable into a name, V5 stale, V6 missing contract); output `<file>:<line> [Vn] ... FIX: ...` plus `TOTALS`, `KEEP-AS-IS`, `UNCOVERED`; never regex-apply, literal old/new pairs requiring exactly one match, read the resulting sentence; `model_hash.py` must not move.

### Area 5 verdict

General (formalizable as "agent as researcher" protocols): a pre-registered measurement ritual (decompose, price, same-host A/B, min over reps, record win or refutation); a remote-host validation loop with explicit invariants, detached launch, marker protocol, deadline-bounded babysitter, and incremental pulls; a byte-identity oracle captured before editing; a package-boundary verification against the last shipped artifact; an adversarial review fan-out with conventions in the brief and mandatory verification of each finding; a numeric design ratchet read as questions; a feature gate that prototypes outside the core and pre-registers kill criteria; a comment audit with fixed categories and a required KEEP/UNCOVERED tally.
bonsai-specific: the profile buckets and engagement lines; card names and image tags; the cells worth driving; CCN 12 threshold; the three comment tags.
Missing: skills are prose, not executable (no harness runs a skill's steps or checks its postconditions); no skill records its own run (which gates ran, on which tree) except by convention in commit `Ran:` lines; pod babysitting is described but the watcher is not a committed script; no shared "experiment record" schema linking a perf round's profiled ledger cells, the PR, and the decision entry.

### Area 6 verdict

General: dated evidence writeups with host, cost, raw file, and sha; a results directory whose committed set is exactly what the registry and renderers consume; hash gates at three layers (cross-architecture, across wheel legs, CI vs rented GPU); a release gate that refuses to publish unless standings are fresh for the exact version; a GPU validation job that rents, smokes, compares, tears down, and sweeps; a paths-filter job so required checks always report.

## Cross-cutting summary for ml-lab

Reusable mechanisms, in the order they would be generalized: (1) schema-versioned additive JSONL rows with `git_sha, cmd, host{cgroup-aware}, knobs_hash`; (2) spec -> job expansion with subprocess isolation, status rows, and identity-keyed resume; (3) a standings registry per axis with current file, measured sha, host, date, release, source-set digest, reference versions, decision pointer, and companion evidence; (4) three gates reading one math module: claim-time tag vs `as_of_decision`, release-time `refreshed_for` or digest-unchanged, planner `--stale`; (5) three-arm interleaved A/B with fixed anchor, min over reps, two bands, and a citation requirement on a moved verdict; (6) carry-forward stamps with mechanical evidence refusals; (7) render-or-fail-on-drift generators with a use-it-or-remove-it manifest; (8) invariants generated from test markers; (9) a fixed-input model hash as the byte-identity oracle, gated across architectures, wheel legs, and a rented GPU; (10) a numeric design ratchet and a mechanical comment policy; (11) remote host rituals: sha assertion, capability gates that quarantine partial output, DONE/FAIL markers, deadline-bounded polling, finally-teardown and sweep; (12) an append-only decision ledger with status, Rejected, Reopener, and machine-read tags.

Gaps a framework must close, consolidated: no run database (files plus registry only); month-keyed file names (collisions within a month, acknowledged twice as owed); unpinned, unladdered CPU pod create; A/B rows without a host block; no reachability check of the registry sha against main; mixed short/long `git_sha` compared by prefix; `knobs_hash` over spec defaults not cells; `as_of_decision` and decision numbers assigned by hand; two independent pod-rental implementations (driver vs `validate-cuda`); skills and rituals are prose with no execution record; no row schema validation at write or render time; probe outputs untracked and unindexed; no per-session cost or duration record.
